メッセージ編集関連

カラムの幅を変更して保存しましたが、ファイルの内容が変わっていません。

仕様です。 カラムの幅を変更しても、その内容はmstxtファイルに保存されずに、 別の個人設定ファイルに保存されています。 編集のやりやすい環境は各個人によって違うため、 ファイルを共有したとしても、このような設定情報まで 共有されることがないように設計されています。

ファイル関連

データを特定の形式でエクスポートできますか？

メッセージファイル(*.mstxt)などを別の形式でエクスポートして、 Message Studioが扱えない人(例えばデバッグ担当者、声優など)に引き渡す必要がある場合があります。 しかし、データのエクスポートは、ゲームの仕様や渡す相手によって仕様が大きく異なるため、 Message Studioでは標準機能としてデータのエクスポートをサポートしていません。

Message Studioでデータのエクスポートを行うにはプラグインとして機能を実装するか、 あるいはメッセージファイル(*.mstxt)をXMLファイルとして読み込み、それを変換する必要があります。 プラグインによる実装を行う場合、メッセージファイル(*.mstxt)を変換してHTMLファイルを 出力するためのサンプルプログラムが、samplesディレクトリ以下に収められています。 また、XMLファイルの仕様書はヘルプに記載があります。

非常に単純な、タブ区切りファイル(*.tsv)形式でのエクスポートを行うためのプラグインは、 公式リリースされている、ミニプラグイン集の中にも収められています。

Perlなどを使って外部からファイルを書き換えても問題ないですか？

外部からXML仕様書に従ってファイルを書き換えることは問題ありません。 ただし、Message Studioが立ち上がっている最中に外部から書き換えを行うと、 問題が発生する可能性があります。

ビルドサーバなど、Message Studioが確実に立ち上がっていないことが保証できる場合は、 特にこの点を考慮する必要はありませんが、ユーザーがMessage Studioを利用している可能性が ある場合、Message Studioを確実に終了しておく必要があります。 ミニプラグイン集の中には、Message Studioを終了させる信号を送るための、 KillSignalSenderアプリケーションと、その信号を受信するためのKillSignalReceiverプラグインが 同梱されています。それらを利用することで、Message Studioを確実に終了した状態に出来ます。

スタイルと幅計算関連

幅計算はどのぐらい信頼できますか？

スタイルおよび幅計算機能を利用することで、どのぐらいの大きさで画面上に表示されるかを Message Studio上で事前に知ることが出来ます。 ところが、この機能は、あくまでも画面上にどのように表示されるかを推測しているにすぎないため、 参考にはできますが信頼性が高いとはいえません。

表示されるテキストは必ず画面上で確認し、 正確に全てのテキストが枠内に収まっていることを確かめた上で 製品を出荷するようにしてください。

フォントサイズを変更する特殊なタグを利用したい

ゲームによっては、フォントサイズを変更するための独自のタグを用いることがあります。 それをMessage Studioのプレビューや幅計算でも適用させるためには、 プラグインによる実装を行う必要があります。

ゲーム中にてどのようにフォントの大きさを計算するのがよいでしょうか？

Nintendo Ware for Revolutionや、TWL Systemをスタイルに設定すると、 スタイルとしてもフォントのサイズを設定できる項目があります。 それにも関わらず、フォントサイズをパーセント単位で変更可能なタグもあります。 ゲームでフォントサイズを設定する場合、これらを掛け合わせて以下のような数式としてください。

( fontSize / 100 ) * fontScale

上の数式の中で、fontSizeはタグによって設定されたフォントサイズを表します。 fontSizeはパーセント単位で数値が来ますので、100で割った値を掛け合わせます。 もう一方の、fontScale値は、スタイルに設定された値が入ります。

チーム管理機能関連

Can other clients be used?

In addition to the Message Studio, there is a way to access the Subversion (The version management system that the Message Studio uses). For example, the client software Tortoise SVN can be used to access the Subversion. Message Studio does not use a proprietary method to enable the team management feature so these other software titles can be used at the same time.

However, in such case that a user would like to use another type of client software, please be careful about the Subversion version information. If the version information of the working copy is incorrect, it might not be possible to gain access using another client software. Especially because Message Studio uses a more recent Subversion version, it might be that after the Message Studio accesses the working copy, it is possible that a problem might occur afterwards. In this case, please try doing things like updating the client software version. Also, there are times when the Subversion version number and the Client Software version number do not correspond. Please check the Client Software manual to see if it is compatible with the Subversion. The version number of the Subversion used by the Message Studio can be checked by choosing "Version Information" in the "Help" menu.

The file says "Locked"

If a certain action cannot be completed, the working copy will be locked. And it might be possible that the team related featured might not be useable. This is the error message that appears not when the file on the server is locked but the file on the user's PC is locked. If this happens, in order to unlock the lock, the user will need to run the "Clean Up" command. By doing this, the lock on the PC will be unlocked and the Team Management functions will again be useable. For more informatoin on the lock feature, see the Basic Controls page.

I cannot change the upper and lower case in file names

If the Team Management function is being used, you will not be able to change the upper and lower case lettering in the Project Explorer. For example, you cannot change "MyFile.mstxt" to "MYFILE.mstxt."

This occurs because, while the Subversion file system does recognize upper and lower case characters, the Window file system does not. As long as Windows is being used, there is no getting around this problem. Using other Subversion Client Software (TortoiseSVN, for example) will not make a difference.

In order to change upper and lower case characters using Message Studio, please follow the below steps.

  • Change MyFile.mstxt to MyFile1.mstxt in the Project Explorer.
  • Choose "Commit" (Check In All Changes?) from "Team" (Sharing?) and upload the file to the server once.
  • Return to the project explorer and change MyFile1.mstxt to MYFILE.mstxt. At this time, please check that an error does not occur.
  • Pick "Commit" (Check In All Changes?) from "Team" (Sharing).

Can you work offline?

The Message Studio uses the team management function and if the server and the network are not connected, several features that use the server will not be accessible. Those features are "Update," "Commit," "Checkout," "Display Log," and "Display Difference." Features like "Clean Up" "Undo all edits," and other such features do not use the server so they can be used. Outside of these, text can be edited without a problem. You can also commit data that you have revised once the server is connected.

If the project settings are such that a file will automatically be updated when it is opened, an error message will appear in the beginning alerting you to the fact that it cannot connect to the server. If you close the error dialog box, you will be able to edit the file as usual.

However, while it is technically possible to work in the files without being connected to the network, working on a laptop outside of the office opens the project up to the possibility of information getting out. There is a possibility that the text that appears in a game reveals a lot about what happened in the game so, so we do not recommend working offline. Also, the files that the Message Studio uses are structured for general use and are not encrypted. For this reason, if someone has the know-how, even without the Message Studio, they should be able to take the data and make it something visible.

When I work in a file, will be changes appear in the working copy?

Say for example, a user is able to set a project's management settings using the Subversion. Under these conditions, if that user can add or delete files and folders and change file names in the Project Explorer, in the background, in exchange for being able to generate control commands, it is structured so that controls can be implemented via the Subversion. In other words, this means that the user would be able to freely use the svn add command to add a file.

As a result, action taken through the Project Explorer are essentially cued up to be uploaded to the server the next time files are commited. Of course, once this is done it is also possible to use other client software to commit the files.

It takes a while to update the files. Can something be done?

Subversion software while being very convenient can become weighed down when there are many files to manage and can take a while to update if this happens. This is a basic issue with the Subversion so it is very difficult to alleviate but by manipulating the directory structure, it is possible to make is less likely for a problem to arise.

When converting, the number of resource files that are output can increase so it can be beneficial to set those files to be ignored. If you are going to do this, add the property svn:ignore to the Subversion directory and and set the names of files and directories to be ignored as wild cards. This control cannot be performed through the Message Studio so please do so using another client software.

It is best to only place necessary files below the directory containing the Project File. The Message Studio is set up so that when an svn update is performed, it updates everything under that project directory. For this reason, if there are extraneous files being managed in the directory containing the Project File (for example, the program source code) these files will also be included in the update and therefore take some time.
