About the Team Management Function

In no situation would the text for all languages be created by one person.. In most instances, the text will first be created and then confirrmed with the cooperation of many. However, if there are multiple people accessing a file, then no one will know which file, last revised by which user, is the lastest version.

This is where the Team Management Feature comes in. This feature makes it possible for multiple users to access the files at the same time. Changes made to the files are shared and the system can also track who made what changes and when. With the Message Studio, a system called the "Subversion" which allows for team management from the application can be accessed. Because of this, team management features, which used to be rather complicated, have been made simpler.

About the Subversion

A Subversion is one of the "Version Management Systems" frequently used in software development for example. (It's called SCM: Source Code Management). A version management system is typically software used for data management in program development, etc, and is allows multiple users simultaneous access. Through the use of the Subversion, the change history (versions) are all saved to the server, making revising the document easier. In addition to Subversions, this kind of version management system also exists in tools like Alienbrain developed by NXN Software of Germany.

For those who have never used a Subversion before, please start by reading this explanation page.

For more detailed information on how Subversions work, we recommend refering to the Subversion Book. This can be accessed for free online and includes a load of information. (However, for normal use of the Message Studio, the information contained in this Help should be sufficient.)

For those who have used the MMS

At Nintendo EAD, we have created a tool that allows simultaneous translation called the MMS. The team management feature of the Message Studio and the MMS are essentially the same but there are a few points that differ. Here is a summary of those points.

About the software structure

The MMS is a tool created to support the Message Editor and it only added the team management function. For this reason, even if the MMS was being used, the Message Editor also had to be supplied and the two tools used together. With the Message Studio the editing and team management tools are combined so there isn't a need to use two tools.

Also, with the MMS, though it used a Subversion, in order to access the Subversion, it required that additional software be prepared. With the Message Studio, software to access the Subversion is not needed.

About the Directory Structure

With the MMS, it was necessary to create a directory for each language and files were divided by language when saved. With the Message Studio, there are no limits to the directory structure and settings based on this do not need to be determined. Also, all users will access the same files.

About "Merging"

With the MMS and the Message Studio, the meaning of "Merging" differs. As mentioned before, with the MMS, because files were managed separately by language, it was necessary to pull down the text for other languages to the users PC. This is what was called Merging with the MMS.

With the Message Studio, it is no longer necessary to Merge in the same way that it was with the MMS. This is because all users are accessing the same file. If all users are accessing the same file, the possibility that people are making edits at the same time. Compiling these updates seamlessly is that is called Merging in the Message Studio. (This is the same thing it's called in the case of a Subversion).

The Subversion running in the backend of the Message Studio is high functioning and allows for edits by multiple users to be compiled seamlessly. Even though multiple users might edit a file, most of these revisions will be compiled without issue. In other words, merging in this instance isn't done manually but it happens automatically by the system when the data is pulled off the server (called "updating"). The only time that merging would happen manually would only be when multiple users edit the same area at the same time (for example, when multiple users change the same cell's contents at the same time, etc.).
