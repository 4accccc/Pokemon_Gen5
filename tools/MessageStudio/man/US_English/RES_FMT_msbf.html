Flowchart Binary Format

The format of flowchart binary files (*.msbf) will be explained here. They are configured based on the block format so please refer to that explanation as well. In order to create a flowchart binary file, it is necessary to make it possible to use a separate flowchart plug-in on the project.

Normally it's not necessary to worry about the contents of these pages but it will help to understand libms when you use them. When accessing the binary format, using a libms API can make it easier to access it.

Flowchart Node Block (FLW2)

This block maintains how the flowchart node (a singular box on the flowchart) is connected. Also, this block only stores information on how the block is connected. Layout coordinates (location data) is all discarded. The flowchart nodes are all assigned consecutive index numbers from the beginning.

Count Data

First the count data will be saved.


NODE NUMThe flow chart node count saved to this block is displayed. 0 to 65535 are saved. This flowchart node data is saved to the saved to the first half of the block.
CASE NUMThis displays the jump count saved to this block. Many branch paths can be set with the flowchart branch node. The number is represented by the "jump target index information" in the second half of the block.
RESERVEDReserved area. Data might be added to this location in the future.

After the count data, flowchart node information will be inserted as a programming array. A singular flowchart node is saved as a 12-byte fixed length cell and is saved in the order specified by the index number. Among these, the branch nodes will exceed 12-bytes due to the branch count. In addition to this range, there is another area where branch target information in saved.

Node data is structured in the following way.



NODE TYPEThe node type is included. This range is read first and then determine which node should be designated.
PRM TYPEパラメータの種類が入ります。 標準のフローチャートでは、分岐ノードとイベントノードにパラメータを指定できます。
Type Description
BYTE4 The value representing this type (0) is used.
BYTE22 The value representing this type (1) is used.
BYTE211 The value representing this type (2) is used.
BYTE112 The value representing this type (3) is used.
BYTE1111 The value representing this type (4) is used.
TEXT The value representing this type (5) is used.
LIST The value representing this type (6) is used.
PRM VALUEThe value of parameter is saved.
NODE DATAThis meaning will differ depending on the type of node defined by the NODE TYPE. Node specific information is saved. More information on this follows.

Message Node

When then NODE TYPE is 1, that means that that is a message node.

NODE TYPEThe value representing a message (1) is used.
PRM TYPE
PRM VALUE
NEXT IDXIndex to the next node. (When one does not exist, 0xFFFF will be used.)
CONTENT IDThis is the index to the file name saved to the computer memory in the content data block of the project binary. When one does not exist, 0xFFFF will be used.)
TEXT IDXMessage index within the message binary file. (When one does not exist, 0xFFFF will be used.)
RESERVED(Not currently used)

Branch Node

When the NODE TYPE is 2, that means that it is a branch node.

NODE TYPEThe value representing a branch (2) is used.
PRM TYPE
PRM VALUE
NEXT IDXIndex to the next node. (not used, always 0xFFFF in branch node.)
QUERY IDThis ID identifies the conditional branch (query) set for the project.
CASE NUMWhen there is a branch, there will be multiple node candidates. This value represents the number of branch targets there are for the following node candidate.
CASE IDXThis is the index to the next node that can be accessed through the node index. When there is a branch, the index will be preceded by a CASE NUM candidate. (When a branch does not exist, 0xFFFF will be used.)
RESERVED(Not currently used.)

Event Node

When the NODE TYPE is 3, that means it's a event node.

NODE TYPEThe value representing an event is used.
PRM TYPE
PRM VALUE
NEXT INDEXThis is the index to the next node. (When one does not exist, 0xFFFF will be used.)
EVENT IDThis ID represents an event that is set by the project.
RESERVED(Not currently used)

Entry Node

When the NODE TYPE is 4, that represents an entry node type.

NODE TYPEThe value representing an entry (4) is used.
PRM TYPE
PRM VALUE
NEXT INDEXThis is the index to the next node. (When one does not exist, 0xFFFF will be used.)
RESERVED(Not currently used)

Jump node

When the NODE TYPE is 5, that represents a jump node.

NODE TYPEThe value representing a jump (5) is used.
PRM TYPE
PRM VALUE
NEXT INDEXThe index to the next node. (When one does not exist, 0xFFFF is used.)
CONTENT IDThe content id of message file include next entry node.
RESERVED(Currently not used.)

Branch information and text parameter value.

After this data, the branch node branch index list will be entered at the end.



This data is set as 2-byte arrays. They each show branch target flow chart node index numbers and when there isn't a connection 0xFFFF is used.

分岐情報に続く、テキスト型のパラメータ値は、NULL終端のASCII文字列となっています。この文字列は、ノードのパラメータのタイプがテキストの場合に取得されるパラメータ値を、データ部先頭からのオフセット値として利用することで取得できます。

Flow chart entry block (FEN1)



This block serves to carry through the flow chart node index number using the entry node name as its basis. The basic structure of the data is very similar to the label block (LBL1) of the message binary file (*.msbt) so please refer to that.
