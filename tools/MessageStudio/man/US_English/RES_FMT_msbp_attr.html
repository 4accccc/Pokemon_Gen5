Project Binary Attribute Information

It is possible to export attribute data to the message binary as an attribute block (ATR1) but there is no telling what size attribute will be positioned in what order. Normally, the structure of this type of information has it output as a header file (*.h) and and the attribute data is accessed but in this case, each time the attribute settings are changed, the program will need to be re-compiled once again.

Attribute information that can be output to the project binary includes the attribute size and arrangement data which are saved and used to address attribute setting changes without the program having to be compiled.

Also, if the attribute is a list type, it is also possible to associate index numbers and item names for that attribute.

Attribute Name Block (ALB1)

It is the same structure as the message binary LBL block.

It is possible to associate the attribute name block (AfLB1) with the attribute name and the related index number. The index number is the number that represents the attribute data storage sequence in the below mentioned attribute information block (ATI2). Index numbers start with 0.

Attribute names are assigned using ASCII code and contain 255 characters or less, and can be set using the Message Studio. For details see attribute settings. Because the attribute name character string can be looked up using a hash value, even though the attribute count may go up, this block should be searchable without much of a loss of efficiency.

After the block header, the style name block will have the following data structure.

※That values in this image are random.

HASH TABLE SIZEThe hash table size will be explained. The hash table size can be set using the Message Studio and depending on the size the speed and memory usage can be adjusted. The default value is 29 but please try to set it as a prime number. This is 4-bytes of data.

Depending on the value assigned to the hash table, the following 8-bytes of data will be repeated. If the hash table size is 29, the total of this section will be 232-bytes.
STYLE NUM IN HASH nThis describes how many attribute names are included in the hash value n. It's 4-bytes.
OFFSET OF HASH nThe offset value of the attribute name information for hash value n is written in 4-bytes. The offset is counted from the beginning of the block. As written above, if the number of attribute names included in the hash value n is 0, the offset value is indefinite.

Immediately after the above mentioned portion is complete, the attribute name and index number map list description will appear. The program will access this region after requesting the offset from the block top hash value.

LENThe attribute will be described in 1-byte.
STYLE NAMEThe attribute name is described. Regardless of the output setting, the attribute name is always written as an ASCII character string and follows the previously mentioned label length volumes only.
STYLE INDEXThe attribute index (ATI2 block appearance position) number is described in 4-bytes.

The above attribute name attribute index combination will appear in order based on the number of attributes there are. There are situations where directly below the offset position sought, different attribute name information exists. This happens because multiple attribute names are registered to a given hash value. In this case, skip the read and see if it matched the next attribute name.

Attribute information block (ATI2)

So that the appropriate data is accessed from the message binary ATR block, necessary information is described in the attribute information block Also, information needed to refer to the list entry data block (ALI) is also described.

Attribute information clocks will have the following data structure following the block header.

※That values in this image are random.

ATTRIBUTE NUMThe attribute data count will be described with 4-bytes.

The following 8-bytes of information will be repeated based on the ATTR NUM value.
TYPE n The attribute configuration will be described with 1-byte. The value and configuration will be addressed per the below.
0x00Codeless 8-bit integer
0x01Codeless 16-bit integer
0x02Codeless 32-bit integer
0x03Coded 8-bit integer
0x04Coded 18-bit integer
0x05Coded 32-bit integer
0x0632bit single precision floating point number
0x0764-bit single precision floating point number
0x08NULL final character
0x09List
PADDING nThis is 1-byte of padding. This is always 0.
INDEX OF LISTINFO nThe list content information index number (appearing in the ALI2 block below) will be described with 4-bytes. However, this value is only valid when the TYPE is equal to 0x09 (in other words, in a list format) and in all other instances will always be equal to 0. If the attributes are in a list format, this index number will be used and the ALI1 block referenced making it possible for the content names to constantly be pulled.
OFFSET OF ATTR IN STRUCTURE nThe starting point of the ATR1 block structure of attribute data will be described in 4-bytes.

One way of getting the appropriate data from the ATR1 block of a message binary is to use this ATI2 block. In your program, you can get data from the ATR1 block by using OFFSET OF ATTR IN ATR STRUCTURE to get the offset position of attributes within the structure, and by using TYPE to determine the type and size of the data. The ATI2 block is normally used in combination with the ALB1 block. These methods make it possible to access the attribute data within strings."

With game projects where the sequence of attribute data is frequently being updated, by using an ATI2 block to reference the attribute data, there is the advantage of not needing to create new builds in order to update the message resources. However, accessing data will become significantly less efficient than when accessed by simply using the structure defined by the attribute definition header. In other words, on a case by case basis, use a (C/C++) macro to access attribute data, and when using a debug build use character strings, and when using a resource build use a member variable definition, etc. to achieve the most benefit out of what you are doing.

List entry data block (ALI2)

The names of the entries in a attribute list are stored to the list entry data block. This information can be used when, for example, you want to use an entry name for a file name.

A list entry data block following the block header will have the following data structure.

※That values in this image are random.

ITEMINFO NUMList entry data will be described as 4-bytes. This equal to the attribute list count.
OFFSET OF ITEMINFO nCounting from the beginning of this block, the offset value where the list entry data starts will be described in 4-bytes.. This information will be repeated ITEMINFO NUM times.

In addition, the contents of the list entry data will have the following data structure.

ITEM NUMThe number of entries in this list will be described in 4-bytes.
OFFSET OF ITEM NAME mCounting from the beginning of this list entry data, the offset value where the entry names start will be described in 4-bytes.
ITEM NAME mThe actual entry name will appear. The encoding format will be ASCII with a NULL terminal edge.
