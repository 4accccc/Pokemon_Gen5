Using the Team Management Features

Before Starting to Use the Team Management Features

There are three ways to start using MessageStudio's team management features. Choose the option below that is right for your circumstances to start using these features.

  • If you are not the team administrator (perhaps you are a translator or in some other role instead), join the team taskflow by selecting "Check Out Project."
  • If you are the team administrator, select "Check In."
  • If you are a programmer or in some other role that shares with other Subversion clients, you can also use the auto-detect features.

Checking in uploads data to the server, and checking out downloads data from the server. But you should only check in or out once, as the first step in participating in a project. After the initial checkin or checkout, use "Update" and "Commit" to download and upload data. (For details, see Basic Team Management Operations and related pages.)

Once the team management features have been enabled by one of the methods above, the content icons in the Project Explorer will be marked as shown in the figure. These marks change to show the current state of the content files. See Basic Team Management Operations for details on these marks.

Once the team management features are enabled, the directory specified as the working directory (copied for editing) is put under the control of MessageStudio's team management features. Do not copy, delete, or rename any of the files in this directory from within Windows Explorer.

Deleting or otherwise altering these files in Windows Explorer can cause inconsistencies in the management data, leading to problems in MessageStudio. Created *.svn directories also contain management data. Moving or deleting these directories, or altering their contents, can lead to similar inconsistencies and problems during operation. Once team management features are enabled, carry out all file operations from within MessageStudio as much as possible.

Should any such problems arise, resolve them by deleting all files including *.svn directories from within the working directory, and then checking out the project again.

Checkout

Checkout is the first step to participating in an existing project. Checking out downloads a project being managed by the team management system from the server. To check out a project, click the "Sharing" menu and select "Check Out Project."

The following items must be configured to check out a project. Enter the values given to you by your team administrator, and click the "OK" button.



SettingDescription
System TypeThis drop-down selects which team management system to use from all those supported by MessageStudio. At present, Subversion is the only supported system.
Repository AddressThe repository address is the address of the server that manages the project. Any future Commit or Update operations are performed against this address. Enter the address given to you by your team administrator.
Working Copy LocationThe Working Copy location is the path to the working directory, where you can edit the project. The location of this directory has no impact on either the server or the work itself, so you can freely specify any convenient location.
User NameYou may need to provide a user name and password to access a repository. If required, enter the user name given to you by your team administrator.
PasswordYou may need to provide a user name and password to access a repository. If required, enter the password given to you by your team administrator.
Proxy SettingsDepending on the network configuration, you may need to connect to the server via a proxy server. Specify the proxy settings here. Use the settings provided by your network administrator. See Connecting via Proxy for details.

Checkin

Checking in immediately after a repository is created by the network administrator will upload previously created files that are not under team management to the empty repository. To check in, click the "Sharing" menu and select "Check In Project."

This will open the following dialog box. This is basically the same as the dialog box described above, but it also includes a field for comments about the data being uploaded to the server. The comment text entered here can be viewed by others, so we recommend that the comment be easy to understand.

For Advanced Users

Once a project is checked in, the directory where the project file (*.msproj) is located is used as the working directory. All files and directories registered as the project's content files are then copied to this working directory and put into the "Add" state, after which all data is directly committed. If additional files outside of these content files (such as font files) must also be managed in Subversion, use TortoiseSVN or some other Subversion client software to commit that data.

Using Projects Checked Out By Other Software

If a project file is already checked out from Subversion using some other software besides MessageStudio, the following dialog box will appear when you attempt to open the project file.

If you need to access team management features from MessageStudio, enter the user name and password for accessing the repository and click the "Use Sharing Features" button.

MessageStudio's team management features can also be used by other client software, allowing you to manage team resources without using MessageStudio itself. In such cases, click the "Don't Use Sharing Features" button.
