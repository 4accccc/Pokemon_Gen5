Project Binary - Tag Data

The tag group, tag, and parameter numbers can all be associated with the names that correspond to each. List-type parameter values can also be associated with the corresponding item names.

Tag Group Data Block (TGG2)

The tag group data block stores the tag data index numbers of the tags included in tag groups, as well as the tag group name. This block is needed when getting the name of a tag group from the tag group's number in the message binary TXT block. It is also needed to extract data from the tag data block (TAG2).

After the block header, the data in the tag group data block has the following structure.

Note: The values in this image are purely for purposes of illustration.

GROUPINFO NUMThese 2 bytes hold the number of tag group data items. This is equivalent to the number of tag groups.
PADDING2 bytes of padding. The value is always 0 (zero).
OFFSET OF GROUPINFO nOffsets from the start of this block to the beginning of the data for each particular tag group are stored in chunks of 4 bytes each. The number of these is equal to GROUPINFO NUM.

The individual tag group data items have the following structure.

TAG NUMThese 2 bytes hold the number of tags included in this tag group.
PADDING n2 bytes of padding. The value is always 0 (zero).
INDEX OF TAGINFO mThese index numbers indicate where the individual tags of this tag group are located in the tag data block (TAG2). The number of these is equal to TAG NUM. These correspond to the "n" value of the tag data block's OFFSET OF TAG INFO n.
GROUP NAMEThis stores the tag group name. The string is encoded in the ASCII charset. NULL-terminated.
PADDING nPadding. This is 2 bytes in the figure, but this padding is used to align to 4-byte alignment, so it may range from a minimum of 0 (zero) to a maximum of 3 bytes in length. The value is always 0 (zero).

Tag Data Block (TAG2)

The basic structure is the same as the tag group data block (TGG2).

The tag data block stores the parameter data index numbers of the parameters included in tags, as well as the tag name. This block is needed when getting the name of a tag from the tag's number in the message binary TXT block. It is also needed to extract data from the tag parameter data block (TGP2).

After the block header, the data in the tag data block has the following structure.

Note: The values in this image are purely for purposes of illustration.

TAG INFO NUMThese 2 bytes hold the number of tag data items. This is equivalent to the number of tags.
PADDING2 bytes of padding. The value is always 0 (zero).
OFFSET OF TAG INFO nOffsets from the start of this block to the beginning of the data for each particular tag are stored in chunks of 4 bytes each. The number of these is equal to TAG INFO NUM.

The individual tag data items have the following structure.

PARAM NUMThese 2 bytes hold the number of tag parameters included in this tag.
PADDING n2 bytes of padding. The value is always 0 (zero).
INDEX OF PARAM INFO mThese index numbers indicate where the individual parameters of this tag are located in the tag parameter data block (TGP2). The number of these is equal to PARAM NUM. This corresponds to the "n" value of the parameter data block's OFFSET OF PARAM INFO n.
TAG NAMEThis stores the tag name. The string is encoded in the ASCII charset. NULL-terminated.
PADDING nPadding. This is 2 bytes in the figure, but this padding is used to align to 4-byte alignment, so it may range from a minimum of 0 (zero) to a maximum of 3 bytes in length. The value is always 0 (zero).

Tag Parameter Data Block (TGP2)

The basic structure is the same as the tag group data block (TGG2).

The tag parameter data block stores the list name index numbers of the list items included in parameters, as well as the parameter name. This block is needed when getting the name of a parameter from the tag parameter's number in the message binary TXT block. It is also needed to extract list item names from the tag list item name block (TGL2).

After the block header, the data in the tag parameter data block has the following structure.

Note: The values in this image are purely for purposes of illustration.

PARAM INFO NUMThese 2 bytes hold the number of tag parameter data items. This is equivalent to the number of tag parameters.
PADDING2 bytes of padding. The value is always 0 (zero).
OFFSET OF PARAM INFO nOffsets from the start of this block to the beginning of the data for each particular tag parameter are stored in chunks of 4 bytes each. The number of these is equal to PARAM INFO NUM.

The individual tag parameter data items have the following structure.

ITEM NUMThese 2 bytes hold the number of list items included in this parameter.
PADDING n2 bytes of padding. The value is always 0 (zero).
INDEX OF ITEM NAME mThese index numbers indicate where the individual list items of this parameter are located in the tag list item name block (TGL2). The number of these is equal to ITEM NUM. This corresponds to the "n" value of the tag list item name block's OFFSET OF ITEM NAME n.
PARAM NAMEThis stores the parameter name. The string is encoded in the ASCII charset. NULL-terminated.
PADDING nPadding. This is 2 bytes in the figure, but this padding is used to align to 4-byte alignment, so it may range from a minimum of 0 (zero) to a maximum of 3 bytes in length. The value is always 0 (zero).

Tag List Item Name Block (TGL2)

The tag list item name block stores the item names for list-type tag parameters. This block is needed to get the name of the item corresponding to a specific list-type tag parameter value in the message binary TXT block.

After the block header, the data in the tag list item name block has the following structure.

Note: The values in this image are purely for purposes of illustration.

ITEM NUM These 2 bytes store the number of list items. This is equal to the total number of list items in all list-type parameters.
PADDING 2 bytes of padding. The value is always 0 (zero).
OFFSET OF ITEM NAME nOffsets from the start of the block to the beginning of a particular item name are stored in chunks of 4 bytes each. The number of these is equal to ITEM NUM.
ITEM NAME nThis holds the actual item name. The string is encoded in the ASCII charset. NULL-terminated.
