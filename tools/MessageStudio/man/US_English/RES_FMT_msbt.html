Message Binary Format

This section describes the message binary file (*.msbt) format. This format is based on the data block format, so it may be useful to also refer to the description of the block format. Separate message binary files are converted into resources, one per each language setting. This allows a game to launch in a mode that supports a given language by loading the files corresponding to that language at file load time.

You do not generally need to be aware of the information in this section, but understanding these concepts can be very helpful when using libms. Use the libms functions to easily access binary formats.

Label Block (LBL1)

The label block (LBL1) stores labels and can associate those labels with their corresponding index numbers. The index numbers indicate the sequential order in which messages are stored in the text block (TXT2), described further below. Index numbering starts from 0 (zero).

Label names can be any ASCII string up to 255 characters long. They can be set within MessageStudio. For details, see Basic Operations for Editing Messages. Data is looked up in this block on the basis of the hash value of the label string, so an increase in the number of labels has only a small impact on search efficiency.

After the block header, the data in the label block has the following structure.



HASH TABLE SIZEThe size of the hash table. The hash table size can be configured in MessageStudio, and changing it allows you to adjust processing speed and memory usage. The default value is 101. If you change it to another value, set a prime number if possible. 4 bytes.

The 8-byte chunk represented by the following data items is repeated HASH TABLE SIZE number of times. If the hash table size is 101, then the total size for this portion is 808 bytes.
TEXT NUM IN HASH nIndicates how many labels are contained in hash value n. 4 bytes.
OFFSET OF HASH nThese 4 bytes indicate the offset(s) to the label data corresponding to hash value n. Offsets are counted from the start of the block. If the TEXT NUM IN HASH is zero for this hash value n, this offset value is undefined.

Immediately after the end of the portion above, the block contains a table listing the labels and their corresponding index numbers. The program accesses this region after deriving the offset of its desired data in the block from the hash value.

L LENThis single byte stores the length of the label.
LABEL NAMELabel name. Label names are always ASCII strings regardless of the output settings, and their length is defined by the L LEN label length value encoded immediately prior.
TEXT INDEXThese 4 bytes store the text index number (the location of the text data's appearance in the TXT1 block).

There is one label and one text index, listed sequentially, for each text string. The derived offset position may sometimes point to the wrong label data. This is because a specific hash value may register multiple labels. In such cases, skip to the next such label and see if that one matches.

Text Block (TXT2)

The text block stores the actual text strings entered by the user. Text strings may include tags. See the section on tags for details.



TEXT NUMThese 4 bytes store the number of text strings.
OFFSET OF TEXT nThese 4 bytes store the offset value showing how far from the start of the block the text string begins. This data is encoded once per each of the text strings whose number is encoded immediately prior. However, the start position of a text string is aligned to the minimum number of bytes per character for that string's specified character encoding. If UTF-8, the strings are not aligned; If UTF-16, the strings are aligned to 2-byte units; and if UTF-32, the strings are aligned to 4-byte units.
TEXT nThis is the actual text string. The text is encoded in the character encoding specified in the message file's binary header. NULL-terminated.

Attribute Block (ATR1)

This block stores attribute data for each text string. This data can be retrieved as a fixed-length structure, one per each text string. This data differs depending on the project settings, so access this block after first outputting the attribute definition header file (*.h) or the project binary file (*.msbp).

If there are NULL-terminated string types defined in the project attribute data, those variable-length strings are not stored here; instead, a 4-byte value is stored in their place. This value stores the offset from the start of the block at which the string begins.





TEXT NUMThe first four bytes store the number of text strings.
STRUCTURE SIZEThis is the size of one fixed-length chunk of data, in bytes. This itself is also 4 bytes.
ATTRIBUTE nThis holds the actual attribute data. This extends for one fixed-length chunk of length STRUCTURE SIZE per each text string.
