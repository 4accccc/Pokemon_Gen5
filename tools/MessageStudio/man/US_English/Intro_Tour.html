Using Message Studio to Create Game Text

The Location of Text in a Game

When creating text to appear in a game, the first questions you should ask yourself are "What is going to be displayed?" and "How is it going to be displayed?" Of course, this information needs to be included in the program. Creating a program requires technical know-how, and a programmer must be brought on board.

"What is going to be displayed?" is the most important piece of information. If this is going to be implemented into the program, the easiest way to do this is to embed it right directly into the program.

const wchar_t* message = L"こんにちは、Message Studio！";
pTextPane->SetString( message );

If you insert the content shown above into your program, that text will be displayed. This is the simplest method, so it also takes the least amount of time to be ready after implementation. However, if you use this method for program development, you will run into major problems later on. For example, take a case where you receive a request from your marketing division to create North American specifications for this game. The program will have the following changes.

#if defined ( MYGAME_REGION_JP )
const wchar_t* message = L"こんにちは、Message Studio！";
#elif defined ( MYGAME_REGION_US )
const wchar_t* message = L"Hello, Message Studio!";
#endif

pTextPane->SetString( message );

And if a European version were also developed, the program would have to accomnodate a number of different countries and languages!

#if defined ( MYGAME_REGION_JP )
const wchar_t* message = L"こんにちは、Message Studio！";
#elif defined ( MYGAME_REGION_US )
const wchar_t* message = L"Hello, Message Studio!";
#elif defined ( MYGAME_REGION_EU )
const wchar_t* message = NULL;
switch( g_langMode )
{
case SC_LANG_ENGLISH:
	message = L"Hello, Message Studio!";
	break;
case SC_LANG_GERMAN:
	message = L"Guten tag, Message Studio!";
	break;
case SC_LANG_FRENCH:
	message = L"Bonjour, Message Studio!";
	break;
case SC_LANG_SPANISH:
	message = L"Buenas tardes, Message Studio!";
	break;
case SC_LANG_ITALIAN:
	message = L"Ciao, Message Studio!";
	break;
case SC_LANG_DUTCH:
	message = L"Goedemiddag, Message Studio!";
	break;
default:
	MYGAME_FAIL( "UNKNOWN LANGUAGE!" );
	break;
}
#endif

pTextPane->SetString( message );

What's more, North American specifications may also also require Spanish and French. Developers in Japan often forget this fact. So you can see how the original code would get very long, even with such a simple greeting. The programmer originally attempted to simplify the task by embedding text directly, but in the end the opposite occurred. If nothing else, no programmer ever wants to see code like this.

It is also more difficult to have this text translated. Once it is translated, you must manually insert the new text in the program. Naturally, it is easier for mistakes to occur, and debugging costs can soar.

Making Text External

As you can see, if strings of characters are embedded directly into a game, cases like the one above can cause further problems down the road. As a solution, text will be managed as external resource files. A resource file is a data file that is used by a game. Images, music, and 3-D model data re all resource files. If text data can be read as a file like this other information, it is also possible to reduce development costs.

Resource files that are implemented in games should be in a format that optimizes the performance of the game. In other words, they should be accessed quickly and use as little memory as possible. And at the same time, they should facilitate efficient editing.

This is where Message Studio comes in. With Message Studio, the workflow like the one above with the programmer at the center, will change in the following way.

For information on the Message Studio game output file, please check the About Resources page.

Summary

Though using Message Studio can complicate the workflow slightly, text management is much faster and more efficient when it's handled by software rather than humans.

Message Studio includes features that let multiple developers simultaneously edit and translate into several languages. (For more information, please see the Team Management Summary page.) For this reason, it isn't necessary to attach files to email and send them to the other participants. Also even if a conflict occurs while editing, it can be resolved efficiently.

This frees programmers from the pressures of managing text, but in return they need to implement a mechanism to load external resource files. There is a library called libms that provides this mechanism and supports multiple platforms. Programmers can use it to handle the analysis of all resources. Basically, by passing the raw data to libms like any other resource file, you can produce text simply by loading files from a Game Pak or DVD.
